## Delivered behavior

Always Play is the fifth explicit Shows-dialog mode. The four old compass directions remain unchanged. Native radios choose 1 Low, 2 Medium, 3 High and 4 Super High; Medium is the first-use default. Start is explicit play intent, Stop leaves already admitted rockets and children intact. Pace changes ease over active simulation time without replacing airborne recipes. The infinity glyph marks the mode; the existing immersive toggle hides all ordinary chrome and leaves one reveal control.

One independent fixed-clock director owns a thirteen-entry shuffled feature bag and one pending intent. Short connectors fill feature cooldowns; high levels use two/three-accent phrase timing with periodic breathing space. No launch backlog, recursive composite, second animation loop, new particle pool or reflection allocation was added. All thirteen recipes, their indices, placement policy and legacy shows remain unchanged.

Admission retains existing capacity and unborn-child reservations. Connectors normally preserve one unit and 520 heads of headroom; solo featured heavy effects escape that soft reserve so Low can still play all thirteen. Soft trail/smoke pressure lengthens spacing, while a 90% head-pressure guard and existing hard caps remain authoritative. Initial intervals are 7.2/3.15/1.35/.82 seconds before jitter, phrasing and pressure. The first logical soak delivered Standard rates of about 6.5/14.8/30.8/52.1 rockets per minute; these are simulation rates, not measured GPU throughput.

A bounded 120-sample feedback window is fed by the existing renderer loop. Sustained p95 above 35ms slows demand in 15% steps; sustained healthy cadence below 34ms restores a step after ten seconds. The thresholds account for Canvas's existing 30fps render schedule; the proposed 25ms recovery threshold would never recover that backend. The director accepts timestamped feedback for deterministic unit replay; snapshots expose the current demand and bounded counters, without logging a session history. The chosen pace remains visible with a quiet limiting explanation.

Manual launch intent stops automatic scheduling even when admission is busy, keeps the requested valid family selected and leaves the committed flight intact. It never queues a manual rocket silently. No rejected auto attempt emits repeated capacity messages.

Preferences migrate versions 1/2 to 3 and validate the saved pace. Running and hidden state are never persisted. Ordinary interactive visits do not auto-start from stored settings or `show=always`; explicit scene/transparent presentation links allowlist `pace=1..4`. Sound, haptics, fullscreen and wake lock use existing independent consent/capability paths. Reduced flashes stays enabled by default, retains the three-second minimum automatic-launch interval and limits reflected energy. Reduced motion disables UI animation and retains existing scene motion policy.

## Retained findings and corrections

`.2` fixed Start display using the interactive stored pace instead of the Display settings selection. `.3` adds a last-admission guard so enabling reduced flashes during fast play delays an already planned cue before admission. Both have regression coverage.

The first `.1` Standard hardware dataset passed paired legacy p95 gates (WebGPU/WebGL 16.8ms, Canvas 33.4ms). A build overlapped some new-mode Canvas collection: that dataset is retained and excluded from final clean Canvas qualification. Its ten-minute WebGPU Super High run had p95 16.8ms and about 50.8 primary admissions/minute, with 13 rendered intervals above 50ms and eight above 100ms. Some preceding CPU submissions were also long. Those observations do not establish a cause or a hitch-free result; final paired transition and Ultra measurements are separate gates.

The first `.3` Ultra manual comparison ran 24 conditions. WebGPU and WebGL passed app-rendered p95 and repeatable transition gates; Canvas failed combined p95 and one burst-window p95 comparison. No repeated new >50ms or >100ms rendered transition was found. This failing dataset remains retained. Its preparation warmed assets and idle water rather than representative Canvas particles. An optional `WATER_PERFORMANCE_WARM_LAUNCH=1` now applies the same Gold Willow particle warm-up to both sources before resetting their seeded scenes. A separate warmed Canvas dataset uses the original assertions; this method correction does not establish the cause of every earlier long frame.

The separate warmed Canvas run completed eight conditions/four counterbalanced pairs and passed both app-rendered percentile gates, observer rAF gates, runtime-error and repeated >50ms/>100ms transition checks. An early Ultra Festival collection was then stopped as invalid: its harness wrote v3 preferences to the older `.11` baseline, which only accepted v1/v2 and therefore retained default reduced flashes. Candidate and baseline workloads differed. The corrected harness supplies v2 to both, asserts quality/reduced-flash settings, resets the seeded Simulation through the existing test-only fixture outside measurement, and freezes its clock until UI Start. No production API or timing assertion was changed.

## Reproducible checks

Use the repository Node 22.16+ runtime. `npm test` includes director/lifecycle/pace tests. `node tests/always-play-soak.mjs <output>` runs two logical hours for each of twelve tier/pace combinations; `ALWAYS_SOAK_MIXED=1` changes comfort settings during those runs. `node tests/always-play-browser.mjs <output>` checks installed native Chrome, with `ALWAYS_URL` selecting the origin. CI explicitly sets `ALWAYS_SOFTWARE=1` and `ALWAYS_BACKENDS=webgl,canvas`, keeping software evidence distinct.

`node tests/always-play-performance.mjs <output>` measures sequential counterbalanced legacy Festival runs and all four new paces through the existing scalar probe. `ALWAYS_PERF_QUALITY` explicitly selects Low/Standard/Ultra; Standard is the harness default. It records exact release manifests, adapter/driver labels, CPU submission separately from render cadence, raw samples, 60-second source-matched videos at each pace and an unrecorded ten-minute Super High peak. Do not run it beside builds, another graphics benchmark or logical soaks. Both isolated preview configs have no production route.

`node tests/always-play-frame-screening.mjs <report.json> <video.webm> ...` provides exploratory whole-frame luminance/red state-difference area measurements. It decodes recorded SDR frames at 30Hz, at quarter resolution, with eight-frame (approximately 267ms) state differences and a moving 341x256 CSS-pixel window approximation. It does not count opposing flash pairs or certify frequency/area conformance. Compression, downsampling and state differencing can miss fine or rapid transitions. [W3C flash guidance](https://www.w3.org/WAI/WCAG22/Understanding/three-flashes-or-below-threshold.html) remains the qualification reference; formal conformance is unqualified.
